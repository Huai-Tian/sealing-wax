# 火漆 · Sealing Wax

简体中文 | [English](README.md) | [AI 协作文档](README_AGENT.md)

> 加密跟随用户，而不是用户跟随加密。

**火漆 · Sealing Wax** 是一层跑在你现有即时通讯软件之上的端到端加密会话层。
消息在你设备上封缄、以密文穿过 IM、只在对方设备上拆封——服务器自始至终拿
不到密钥，也拿不到一个明文字节。

- **无服务器、无账号、无云端**——根本没有后端：没有可注册的，也没有可搜查的
- **默认即焚**——未保存的会话在磁盘上零落盘；退出对话，它从未存在过
- **两端平等**——无组织、无管理员、无策略门；每把钥匙只属于一个会话
- **流量不可识别**——配对帧与数据帧在线路上与随机字节不可区分

## 怎么使用

### 配对一次（每个会话）

1. **A 方**——点**＋新建会话**，输入只有你们俩知道的暗号，复制邀请码，用
   IM 发给对方
2. **B 方**——点**加入会话**，粘贴邀请码，输入同一暗号，复制回复码，发回
3. **A 方**——粘贴回复码；粘贴即完成配对，直接进入对话

暗号应是你们共同记忆中的线下事实——不是曾经在聊天里打过的字。暗号不一致
时握手必然失败；重试只需要一个新回复码，别无代价。

### 对话

- **发消息**——打字，点**加密并复制**，切到 IM 粘贴。比发普通消息多点一次；
  这就是加密在这里的全部代价
- **收消息**——在 IM 里复制密文，切回来；粘贴即自动解密
- **发文件**——选择文件，把封缄后的 `.swx` 分享到 IM；对方导入后，可把原
  文件导出到任意位置
- **核对身份**——9 位验证码常驻对话屏顶栏；与对方念码，或扫它的二维码。
  对不上，说明中间有人——立即停用该会话

### 保存，或焚毁

退出对话时只问一个问题：保存这个会话吗？保存，它就成为首页列表里一个
名字——点开即聊，无仪式、无重新配对。不保存，一切痕迹归零。删除已保存的
会话＝钥匙与历史同删，不可恢复。

### 公共会话（可选）

一个开关，把会话变成一扇门：恒等的静态邀请码，可以贴进你的简介。知道暗号
的人随时可以敲门，每位来访者都得到一把与你独立私聊的钥匙。删除公共会话，
门即拆除；已建立的会话不受任何影响。

## 原理

一句话：两台设备协商出一把 IM 永远学不会的钥匙，然后用它封缄每一条消息。

- **配对**采用 SPAKE2（口令认证密钥交换）。暗号永不上线；中转两端报文的
  中间人推不出钥匙，暗号不符时握手直接失败，而不是产出一把坏钥匙
- **消息**用 ChaCha20-Poly1305 封缄，密钥经 HKDF-SHA256 按需派生——每条
  消息、每个方向都是新钥；重放与乱序由终身流水号拒收
- **流量形态**——每一帧都经掩码处理，IM 运载的字节与随机字节在计算上不可
  区分：它认不出火漆流量，更读不懂它
- **存储**——明文只存在于内存与屏幕。保存的会话，钥匙装在 Android
  Keystore 加密的信封里；未保存的会话，什么都不留

完整线上协议规格与测试向量见 [docs/wire-spec.md](docs/wire-spec.md)。

## 诚实的边界

隐瞒极限的安全工具是负资产。

**防护对象**：IM 服务器与任何网络观察者——读取、篡改、伪造、重放、中继你
的报文。配对期中继过不了暗号这一关；对话屏顶栏的 9 位验证码，是终身可用
的身份仪表盘。

**不防护**：

- 被完全攻破且已解锁的设备——取证工具可能打开已保存的会话
- 通信元数据——谁在和谁说话、何时、多大；你的 IM 本来就在收集这些
- 背叛的对端——拍照、截屏、改装客户端留底明文；任何端到端工具都改变
  不了这一点

另外，暗号是最弱一环：低熵暗号会缩小在线猜测面。PAKE 让每次猜测都必须
在线逐次进行——但一段共同记忆，仍然胜过一个短词。
